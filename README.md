# WELLKNEWS

숏폼으로 소식을 전하는 뉴스 채널 WELLKNEWS의 공식 사이트이자, 여기서 갈라져 나온
개인 프로젝트들이 사는 도메인.

```
wellknews.github.io
│
├── /      WELLKNEWS   입구
└── /;     SEMICOLON   첫 번째 가지
```

두 공간은 같은 저장소에서 빌드되지만 서로 다른 문서다. 색·타이포그래피·모션·폰트까지
공유하는 것이 없고, 방문자는 자기가 들어간 쪽의 자산만 내려받는다.

## 실행

```bash
npm install
npm run dev
```

| 스크립트          | 설명                                     |
| ----------------- | ---------------------------------------- |
| `npm run dev`     | 개발 서버                                |
| `npm run build`   | 배포용 빌드 (`dist/`)                    |
| `npm run preview` | 빌드 결과 미리보기                       |
| `npm run check`   | 포맷 · 린트 · 타입 검사 일괄 실행        |
| `npm run format`  | 코드 포맷 적용                           |
| `npm run assets`  | 양쪽 브랜드의 로고·아이콘·OG 카드 재생성 |

## 구조

```
index.html          입구 문서
;/index.html        세미콜론 문서 — 디렉터리 이름이 곧 주소다
src/
  content/site.ts     입구의 모든 카피와 링크
  styles/             tokens → reset → global 순으로 적용
  components/         컴포넌트 + 같은 이름의 CSS Module
  hooks/              스크롤·포인터 관련 동작
  semicolon/          /; 아래의 모든 것 (아래 참고)
scripts/            이미지 자산 생성 (원본이 바뀔 때만 수동 실행)
                    WELLKNEWS와 SEMICOLON의 파생 자산을 함께 생성
assets/             canonical 로고·OG 배경 원본 (배포되지 않음)
public/media/       WELLKNEWS·SEMICOLON용 최적화 이미지
```

입구의 문구를 고칠 일은 대부분 `src/content/site.ts` 한 파일에서 끝난다.

## 이미지 자산

- `assets/logo.svg`가 로고의 단일 원본이다. 화면용 SVG와 PNG, 파비콘, Apple 아이콘은
  `npm run assets`로 생성한다.
- `assets/og-background-v2.webp`는 OG 카드의 배경판이며 로고와 문구는 생성 스크립트가 정확히
  합성한다. 카피는 프로젝트에 설치된 Pretendard와 Instrument Serif 파일로 직접
  래스터화하므로 운영체제의 대체 글꼴에 영향을 받지 않는다.
- `public/media/`의 404, Hero, REPORT, CHANNELS, ABOUT, SEMICOLON 이미지는 생성형 이미지로 만든
  추상 편집 자산이다. 실제 인물·사건·문서 또는 보도 사진을 나타내지 않는다.
  `hero-newsroom-mobile.webp`는 Hero 원본의 전용 모바일 크롭이다. 생성 프롬프트와
  제약은 `assets/IMAGEGEN.md`에 기록한다.
- `semicolon-interval-cool.webp`는 실제 SESSION의 사진이 아니라, 이어지던 종이가 잠시
  루프를 만드는 홈 전용 개념 정물이다. 빙청색 북향광으로 루프의 ‘맑은 간격’을 표현하며,
  모바일은 4:5 파생 크롭을 쓰고 `semicolon-og-cool.png`는 같은 원본에 canonical 마크만
  합성한다. Hero와 OG 모두 새 파일명을 써서 이전 warm study의 브라우저·메신저 캐시를 피한다.

## 디자인 규칙 — WELLKNEWS

이 사이트는 아래 규칙을 지키는 것을 전제로 만들어졌다. 요소를 추가하기 전에 확인할 것.

1. **생성 이미지는 브랜드 판면이지 보도 증거가 아니다.**
   인물·실제 사건·식별 가능한 장소·읽을 수 있는 문서·가짜 SNS 화면을 만들지 않는다.
   로고와 모든 문구는 이미지에 굽지 않고 HTML 또는 canonical SVG로 올린다.

2. **검정과 종이색의 대비로 섹션의 역할을 구분한다.**
   Hero·CHANNELS·ELSEWHERE는 야간 뉴스룸, REPORT·ABOUT은 편집 지면으로 읽힌다.
   둥근 카드와 장식적 그림자 대신 이미지 크롭, 괘선, 타이포그래피로 깊이를 만든다.

3. **모션의 이동 거리는 짧게 유지한다.**
   리빌은 10px대만 움직이고 나머지 인상은 불투명도와 타이밍이 만든다.
   거리를 키우면 곧바로 슬라이드쇼처럼 읽힌다.

4. **채널 프리뷰는 플랫폼을 흉내 내지 않는다.**
   CHANNELS의 신호 아틀라스는 배포 방식만 추상적으로 암시한다. 실제 게시물이나 플랫폼
   UI가 확보되기 전까지 생성 이미지를 콘텐츠 썸네일처럼 보이게 사용하지 않는다.

5. **모바일은 별도의 구도로 설계한다.**
   Hero는 전용 세로 크롭을 사용하고, hover 기반 CHANNELS 프리뷰는 전체 아틀라스로
   바뀐다. 모든 링크는 44px 터치 영역과 명확한 키보드 포커스를 유지한다.

6. **모든 모션은 `prefers-reduced-motion`을 존중한다.**
   토큰(`--dur-*`)이 일괄 0으로 떨어지고, 각 컴포넌트도 애니메이션 없는 경로를 갖는다.

7. **하위 프로젝트는 ELSEWHERE 목록으로만 소개한다.**
   특정 프로젝트를 위한 섹션을 만들지 않는다. 새 프로젝트가 생기면
   `site.elsewhere.items`에 한 줄을 더할 뿐이다. 목적지의 디자인을 미리 끌어오지도
   않는다 — 문을 통과하기 전까지는 끝까지 WELLKNEWS의 언어를 쓴다.

8. **상단 메뉴는 세 칸이 상한이다.**
   라벨이 12px·0.16em 대문자라 320px 화면에서 네 번째 항목부터 가로 폭을 넘긴다.
   ELSEWHERE가 메뉴에 없는 이유다.

## SEMICOLON (`/;`)

바쁜 삶을 끝내지 않고 잠시 구분하는 기호. 경계를 가진 경험을 하나씩 떼어내 분석하고,
그 사이 이어지는 생각을 남기는 공간이다. 개발자가 만들었지만 코드 에디터를 흉내내지
않고, 하나의 개념 정물과 활자의 여백으로 속도를 만든다.

설명하는 문장을 두지 않는 것이 원칙이다. 무엇을 다루는 자리인지는 기호와 배치가
말하고, 상태를 밝혀야 하는 자리만 숨기지 않고 짧게 적는다.

```
src/semicolon/
  content/site.ts       이 공간의 모든 카피
  content/types.ts      Session · Thread · Meta 타입
  content/sessions.ts   세션 목록 (등록하는 곳)
  content/sessions/     세션 본문 — _template.tsx를 복사해서 쓴다
  content/threads.tsx   스레드 본문과 목록
  styles/               tokens → (공용 reset) → global
  components/           컴포넌트 + 같은 이름의 CSS Module
  pages/                라우트별 화면
  router.tsx            경로 해석 · Link · 깊은 주소 복원
```

### 콘텐츠 체계

|           | SESSION     | THREAD           |
| --------- | ----------- | ---------------- |
| 대상      | 경험한 것   | 생각하고 있는 것 |
| 상태      | 경계가 있다 | 이어지는 중이다  |
| 성격      | 분석        | 단상             |
| 필수 정보 | title       | date             |

길이는 기준이 아니다. 긴 Thread도, 짧은 Session도 있을 수 있다.

### 콘텐츠 추가

CMS나 에디터를 두지 않고 직접 하드코딩한다. 임시방편이 아니라 지금 이 공간의 성격에
맞는 방식이다 — 어떤 세션은 사진이 중심이고 어떤 세션은 문장이 중심이라, 하나의
템플릿에 억지로 맞추는 순간 분석하려던 것을 잃는다.

- **SESSION** — `src/semicolon/content/sessions/_template.tsx`를 복사해 파일을 만들고,
  `content/sessions.ts`의 배열 맨 앞에 등록한다.
- **THREAD** — `src/semicolon/content/threads.tsx` 배열 맨 앞에 항목을 추가한다.
  제목은 없어도 되고, 한 문장이어도 된다.

  `form`으로 그 글이 지면 어디에 앉을지 고른다. 길이가 형태를 정하지는 않는다.

  | form          | 자리                                            |
  | ------------- | ----------------------------------------------- |
  | `note` (기본) | 날짜가 여백 칼럼에 앉고 본문이 그 옆에 온다     |
  | `loud`        | 판면 전체를 쓰고 크게 앉는다. 한 문장짜리 생각  |
  | `aside`       | 오른쪽 안쪽으로 물러나 좁고 낮게 앉는다. 곁가지 |

본문은 `<Prose>` 안의 평범한 JSX다. `p`, `h3`, `blockquote`, `figure`가 공통 리듬을
갖고, 그 밖의 구조는 콘텐츠마다 새로 짜도 된다. 크기·행간·폭은 `--prose-size`,
`--prose-leading`, `--prose-measure`를 바깥에서 정해 바꿀 수 있다 — 어떤 생각은
한 문장이라 크게 앉아야 하고, 어떤 글은 좁게 물러나야 한다.

사진은 `public/images/` 아래에 두고 `/images/파일명.jpg` 로 참조한다. `public/`의
내용은 도메인 루트로 그대로 복사되므로 `/;/` 를 앞에 붙이지 않는다. `width`와
`height`를 적어 두면 사진이 늦게 도착해도 글이 밀리지 않는다. 사진은 본문 폭을
벗어나 단 전체를 쓴다 — 분위기가 아니라 근거로 걸리는 것이라 줄여 걸지 않는다.

### 디자인 규칙 — SEMICOLON

1. **«이것이 반드시 존재해야 하는가»를 먼저 묻는다.**
   미니멀리즘은 스타일이 아니라 의사결정 방식이다. 감성적인 사이트니까 필름 효과를,
   개발자 사이트니까 터미널을, 에디토리얼하니까 번호를 붙이는 식의 판단을 하지 않는다.

2. **글꼴은 두 벌뿐이고, 위아래가 아니라 나란히 놓는다.**
   Hahmlet이 제목·본문·큰 `;`를 맡고, IBM Plex Mono가 날짜·경로·메타데이터·메뉴를
   맡는다. 세리프는 명조이되 코딩 글꼴 쪽으로 기울어 있는 것을 골랐다 — 획 대비가
   낮고 종단이 평평해야 옆에 놓인 고정폭과 한 식구로 읽힌다. 나눔명조·고운바탕처럼
   붓의 흔적이 남은 명조는 옆의 고정폭과 서로 남남이 된다.
   둘을 같은 줄 위에 세우는 것이 핵심이다. 라틴 고정폭과 국문 명조가 한 기준선에
   놓일 때 이 공간의 성격이 가장 잘 드러난다. 모노는 화면을 코드 에디터처럼 만들기
   위한 것이 아니라, 에디토리얼 지면 위에 만든 사람의 사고방식을 남기기 위한 것이다.

3. **정형과 비정형을 개념에 따라 나눈다.**
   SESSION의 행은 같은 종이면과 같은 간격을 반복한다 — 경계를 가진 것들이라 그래야
   한다. THREAD는 날짜와 본문의 위치를 글마다 다르게 둔다(`Thread.form`). 이어지는
   생각에 한 가지 틀을 강제하면 그 순간 게시판이 된다. 차이는 격자선이 아니라 면,
   위치와 여백의 리듬으로 드러낸다.

4. **고정폭의 자간은 라틴과 숫자에만 준다.**
   `2026-04-12`와 `/;/session`은 자간이 넉넉해야 읽히지만, 같은 자간을 한글에 주면
   낱글자가 흩어진다. 메타데이터라도 사람이 쓴 말(장소, 기간)이면 본문의 글자
   체계를 따르게 한다. 사진 설명도 같다 — 자리는 메타데이터지만 문장이다.

5. **판면의 경계는 그리지 않고 만든다.**
   화면 전체를 관통하는 고정 세로선과 전폭 박스선은 쓰지 않는다. 큰 여백, 옅은 빙청색
   면, 활자 크기 차이가 구획을 만든다. 인용문처럼 의미가 분명한 곳에만 짧은 선을 남긴다.

6. **날짜와 메타데이터는 본문 옆 여백 칼럼으로 내린다.**
   인쇄물의 방주(旁註)와 같은 자리다. 읽는 동안 눈은 본문 한 줄기만 따라가고,
   언제 어디였는지는 필요할 때만 곁눈으로 확인하게 된다.

7. **글자에는 색을 얹지 않는다.**
   빙청색·아쿠아는 Hero 편집 정물의 북향광과 옅은 SESSION 면이 맡는다. HTML 글자는
   끝까지 청흑색 단일 잉크이고, 강조색은 글이 끝났다는 표시(`;`)와 현재 메뉴 밑줄·선택
   영역에만 쓴다. 색을 전부 빼도 정보 위계가 무너지지 않아야 한다.

8. **문장으로 설명할 수 있는 것은 기호로 먼저 시도하되, 상태는 숨기지 않는다.**
   SESSION과 THREAD의 차이는 닫힌 면과 열린 여백, 행의 규칙성과 글의 위치가 말한다.
   개념 정의는 각 목록 페이지에서 한 번만 밝힌다. 다만 비어 있는 목록은 장식 기호만
   남기지 않고 현재 상태를 짧게 보여 준다.

9. **움직임은 사람이 시작한다.**
   저절로 도는 애니메이션은 두지 않는다. 링크와 작은 종류 기호만 hover·focus에
   반응하며, 생성 Hero 이미지는 정지한 채 재료와 그림자로 흐름을 표현한다.

10. **없는 정보는 지어내지 않는다.**
    `Meta`의 모든 항목은 선택이다. 채우려고 값을 지어내지 않고, 있는 정보라도
    그 콘텐츠를 이해하는 데 필요할 때만 화면에 올린다. 비어 있는 목록은 간결한 상태
    문장과 충분한 여백으로 완성된 화면처럼 보이게 한다.

11. **`001` 같은 고정 자릿수 번호를 쓰지 않는다.**
    미래의 콘텐츠를 지금의 디자인 규격에 맞추지 않는다. 순서가 의미를 갖게 되는 날
    자연수로 붙이면 된다.

12. **필요해지기 전에 메뉴와 분류를 만들지 않는다.**
    `;` · SESSION · THREAD로 충분하다. ABOUT, ARCHIVE, 카테고리는 탐색이 실제로
    불편해졌을 때 만든다.

### 기호

장식으로 그린 것이 아니라 각자 맡은 일이 있다. 새 기호를 더하기 전에
그 일이 무엇인지 먼저 말할 수 있어야 한다.

| 기호 | 자리                   | 하는 일                      |
| ---- | ---------------------- | ---------------------------- |
| `;`  | 히어로 · 헤더 · 파비콘 | 이 공간의 이름               |
| `;`  | 글 끝                  | 문장이 여기서 잠시 멈춘다    |
| `→`  | 목록의 행 · 절의 머리  | 이 줄이 다른 주소로 이어진다 |
| `←`  | 되돌아가는 링크        | 온 길                        |

### 주소와 라우팅

`;`는 URL 경로에서 인코딩이 필요 없는 문자라 `/;`가 그대로 주소가 된다. 빌드는
`;/index.html`을 두 번째 엔트리로 잡아 `dist/;/index.html`을 만든다.

`/;/session/...` 같은 깊은 주소에는 대응하는 파일이 없어 GitHub Pages가 `404.html`을
돌려준다. 그 페이지가 원래 경로를 `?p=`에 실어 `/;/`로 넘기면 라우터가 주소창을
복원한 뒤 평소처럼 그 화면을 그린다. `?p=`를 달고 다시 404에 도착하면 더 보내지
않는다 — 무한 리다이렉트를 막는 장치다.

개발 서버에서는 `vite.config.ts`의 `semicolon-dev-fallback`이 `/;/...` 요청에 두 번째
문서를 제공한다. 브라우저 주소는 그대로 두므로 깊은 주소와 인코딩된 `/%3B/...` 경로를
배포 환경과 같은 라우터로 바로 검증할 수 있다.

## 접근성 기준

- 본문 색 대비는 배경 기준 최소 6:1 (WCAG AA 4.5:1 상회) — 양쪽 공간 모두
- 최소 글자 크기 12px, 인터랙티브 요소 최소 높이 44px
- 헤드라인 글자 분할 애니메이션은 스크린리더에 원문을 한 번만 노출
- 키보드 포커스에도 호버와 동일한 상태를 표시
- 제목이 없는 Thread도 문서 위계를 잃지 않도록 날짜를 숨은 제목으로 쓴다
- 빈 목록 상태는 시각적으로도 표시하고, 생성 Hero 이미지는 장식이므로 빈 `alt`로 둔다

## 배포

`main` 브랜치에 push하면 GitHub Actions가 포맷·린트·타입 검사를 먼저 돌리고,
통과한 경우에만 빌드해서 GitHub Pages로 배포한다. 검사가 실패하면 배포되지 않는다.
