# EKATA 실현 가능성 검토

검토일: 2026-09-05 · 작성: jippy · 단계: 공식 문서 확인 및 프런트엔드 시안

## 결론

경찰청 안전Dream의 실종검색 API를 이용하는 캠페인은 조건부로 실현 가능하다.
현재 저장소의 GitHub Pages에는 `/ekata/` 독립 문서를 추가할 수 있다.
다만 인증키 발급, 사용 범위 확인, 비밀키를 보호하는 서버 측 중계가 있어야 실제 사건을 노출할 수 있다.
문서의 존재와 인증된 실서비스 호출 성공은 다르다. 이번 작업에서는 인증키가 제공되지 않아 실제 인증 호출을 검증하지 않았다.

에카타는 웰뉴스의 실종아동 찾기 캠페인을 지원하는 웹페이지다.
공식 정보 확인과 제보 창구 연결을 우선 구현하고, 기관이 허용한 범위에서 SNS 게시 운영을 지원한다.

## 확인한 공공기관 API

| 용도             | 공식 명세                                                         | 확인한 내용                                                                                          | 판단                                    |
| ---------------- | ----------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- | --------------------------------------- |
| 실종아동등 검색  | [실종검색 API](https://www.safe182.go.kr/home/api/guide5.do)      | POST `/api/lcm/findChildList.do`; `esntlId`, `authKey`, `rowSize` 필수; 페이지·대상·발생일·장소 검색 | 첫 캠페인의 주 데이터 후보              |
| 실종경보         | [실종경보 API](https://www.safe182.go.kr/home/api/guide3.do)      | POST `/api/lcm/amberList.do`; 경보 발령 정보 제공                                                    | 검색 목록과 별도 기능으로 검토          |
| 공식 검색 템플릿 | [검색 템플릿](https://www.safe182.go.kr/home/api/guide6.do)       | POST `/api/lcm/findChildListT.do`; 공식 상세 페이지로 이동                                           | 재편집 허용이 불명확하면 검토할 대안    |
| 실종신고         | [실종신고 API 문서](https://www.safe182.go.kr/home/api/guide1.do) | 주민번호 등 신고자 측 입력이 포함된 실종 신고 용도                                                   | 목격 제보 전달 API로 대체 사용하지 않음 |

[API 소개](https://www.safe182.go.kr/home/api/guideMain.do)는 개인·기업 연계와 인증키 발급을 안내하며,
각 API 호출 한도를 일일 1,000건으로 명시한다. 신청은 공공데이터포털의 일반 키가 아니라
안전Dream의 인증키 발급 경로에서 시작한다. 발급 소요 시간과 승인 여부는 확인하지 못했다.

검색 명세의 대상 코드 `010`과 `060` 등은 구분해야 한다. 아동 캠페인에서 장애 아동까지 포함하려면
대상 코드와 당시 나이를 실제 응답으로 확인해야 한다. 장기 실종자는 현재 성인이어도 당시 아동일 수
있으므로 현재 나이로 일괄 제외하지 않는다. 공개 문서에는 사진 관련 필드 설명의 혼동도 있고,
안정적인 사건 ID·사진 URL·공개 해제 상태의 충분한 계약이 보이지 않는다. 구현 전에 샘플과
인증 응답을 대조해야 하며, 문서에 없는 필드나 상세 URL 패턴을 추측해 운영하지 않는다.

실종신고 문서는 공개되어 있지만 현재 API 소개에 열거된 세 종류에는 포함되지 않는다.
따라서 해당 신고 API의 현재 신규 제공 여부도 별도 확인 대상이다.

## 이용 조건과 SNS 게시

[안전Dream API 이용약관](https://www.safe182.go.kr/home/api/provision.do) 제5~7조에 따르면:

- 비상업적으로 이용하고 `[자료 출처: 경찰청]`을 표시해야 한다.
- 공공성을 유지하고 독립적으로 노출해야 하며, 제공 내용·URL의 임의 변조 및 오인을 피해야 한다.
- 인증키를 공개하거나 공유하면 안 된다.
- API 이용 승낙만으로 제공 정보의 저작권이나 사용권을 취득하는 것은 아니다.

따라서 웹 API 승인을 SNS 카드 제작·사진 크롭·TTS 낭독·하이라이트 영구 보관의 포괄적 허용으로
해석할 수 없다. `/ekata` 분리만으로 조건 충족이 보장되는 것도 아니다. 광고·수익화 여부와 웰뉴스
계정에 함께 실리는 콘텐츠까지 설명하고 다음을 기관에 문의하는 것이 실제 연결의 다음 단계다.

1. 이 도메인의 독립 비상업 캠페인 및 웰뉴스 계정의 하루 한 건 게시가 가능한지.
2. 인스타그램 카드·스토리·하이라이트로 재게시, 원본 사진 크기 조정, TTS가 허용되는지.
3. 사건 데이터의 단기 캐시와 사진 제공 방식, 삭제·비공개 전환 확인 방법은 무엇인지.
4. 사건 식별자·공식 상세 URL·발견 상태의 보장된 필드와 아동 대상 필터 규칙은 무엇인지.
5. 목격 제보용 공식 연계 수단이 별도로 있는지. 실종신고 API와 혼동하지 않고 문의할 것.

문의는 아직 발송하지 않았다. 이 목록은 검토할 구체적 질문이며 자동으로 외부 메시지를 보내지 않는다.

카드 표기는 `An EKATA campaign` 또는 `Shared by EKATA`가 운영 역할을 잘 나타낸다.
`Supported by EKATA`도 문법상 자연스럽지만 후원 관계로 읽힐 수 있다. 기관과 합의하지 않은
`In partnership with 경찰청`은 사용하지 않는다. 캠페인 크레딧과 필수 경찰청 출처는 별개로 표시한다.

## 서비스 구조

1. GitHub Pages: `/ekata/` 정적 프런트엔드. 오늘의 사건·공식 원문·갱신 시각을 표시하는 화면.
2. 별도 서버 함수: 인증키를 환경 비밀값으로 보관하고 공식 API를 호출. 브라우저 `VITE_*` 변수에 넣지 않는다.
3. 기관이 허용한 단기 캐시: 한도 내 조회를 공유한다. 예를 들어 한 페이지를 10분마다 갱신하면
   하루 144회지만, 전체 페이지 수와 별도 조회를 더한 총합으로 호출 예산을 계산해야 한다.
4. 최신성 규칙: 갱신 실패·만료 시 사건을 숨기고 공식 사이트 링크를 제공한다. 이전 응답을 무기한 남기지 않는다.
5. 게시 운영: 공식 공개 상태 재확인 → 하루 한 건 선정 → 사람이 검토 → SNS 게시 → 게시 URL 기록 →
   공개 종료 시 웹·SNS 게시물 및 하이라이트 정리. API 목록에서 사라졌다는 이유만으로 발견이라고 발표하지 않는다.

공개 저장소의 JSON, Git 이력, 빌드 산출물에 사건 개인정보를 축적하는 동기화 방식은 피한다.
기존 GitHub Pages만으로 비밀키 보호·자동 갱신·제보 전달 서버까지 구현할 수는 없다.
서버 제공자와 비용은 아직 선택하지 않았다. 자동 SNS 게시 및 일일 운영 스케줄도 이번 시안에 포함하지 않는다.

## 제보 창구

초기 제품은 안전Dream 및 182로 직접 연결한다. 긴급 상황은 112로 안내한다.
자체 제보함 없이도 이용자가 담당 기관에 곧바로 연결되는 동작을 만들 수 있다.
에카타가 수집한 제보를 나중에 모아 전달하면 지연·중복 접수와 불필요한 개인정보 보관이 생긴다.

자체 창구를 도입하려면 수신 기관과 전달 방법을 먼저 확정하고 접수 확인, 실패 재전송,
운영 담당자와 대응 시간, 개인정보 처리·보존·삭제 정책을 설계해야 한다.
공개 제보 게시판이나 ‘찾았어요’ 버튼으로 발견 상태를 변경하는 기능은 만들지 않는다.
공식 확인 없는 귀가·발견 소식이나 사건별 성과 집계도 게시하지 않는다.

## 비주얼 컨셉 — 돌아오는 신호

- 바탕 `#10120F`, 네온그린 `#B6FF3B`, 본문 `#EFF2E9`, 정보 판면 `#E9EDDE`.
- 굵은 한글 타이포와 연결된 선을 사용한다. 몬스터의 발톱 로고나 공포·추적 화면을 차용하지 않는다.
- 초록은 연결과 행동의 강조색. 실제 인물 사진에는 색 필터·글리치·생성형 보정·얼굴 크롭을 적용하지 않는다.
- 브랜드 소개는 어두운 판면, 실제 정보 영역은 읽기 쉬운 밝은 판면으로 구분한다.
- 공개 슬로건: **관심이, 돌아오는 길이 되도록.** 방문자가 목적과 행동을 바로 이해하도록 설명한다.
- 사진과 이름은 공식 공개 정보로만 채운다. 시안에도 실제 사건처럼 보이는 가짜 아이를 넣지 않는다.
- 에카타의 산스크리트어 어원은 이번 검토에서 언어학적 검증을 하지 않아 공개 카피에 사실로 단정하지 않았다.

운영 지표는 공식 정보로의 연결, 운영 지속성, 공개 종료 정보의 정리 시간을 먼저 본다.
클릭은 실제 제보나 구조 성과와 구분하고, 확인되지 않은 수치를 표시하지 않는다.

## 이번 브랜치 구현 및 다음 단계

완료: 독립 `/ekata/` 문서, 모바일 대응, 공식 사이트·전화 링크, 캠페인 주소 공유/복사 및 실패 시
수동 복사, FAQ, 웰뉴스 ELSEWHERE 진입점, 독립 파비콘, 인증 확인용 서버 측 스크립트.

현재 화면은 **연동 준비 상태**다. 실제 사건 목록·신고 전송·발견 확인·SNS 자동 게시가 작동한다고 표시하지 않는다.
인증키가 발급되면 로컬의 환경 비밀값 `SAFE182_ESNTL_ID`, `SAFE182_AUTH_KEY`를 설정하고
`node scripts/ekata-api-probe.mjs`로 읽기 전용 인증 확인을 할 수 있다. 이 스크립트는 원문과 개인정보를
출력·저장하지 않는다. 성공 이후 실제 응답 계약을 확인하고 별도 서버 중계를 구현한다.

API 키를 채팅·커밋·공개 `.env` 파일에 붙이지 않는다. 프로브의 인증 호출은 아직 미검증이며,
키가 없는 경우 실패하는 경로와 JavaScript 구문을 확인한다.

시안 확인: `npm run dev -- --host 127.0.0.1` 후 `/ekata/`.
운영 도메인에 배포하려면 검토 후 main 반영이 필요하다. 이번 작업은 새 브랜치 내 로컬 커밋까지만 진행한다.

## 검증 기록

- `npm run build`, `npm run lint`, `npm run typecheck`: 통과.
- 이번 추가·수정 파일의 Prettier 검사: 통과.
- 저장소 전체 `npm run check`: 이번 변경과 무관한 기존 34개 파일의 포맷 차이로 실패.
  해당 검사에서 다음 단계가 생략되므로 린트와 타입 검사는 따로 실행했다.
- 브라우저: 데스크톱 화면, 320·390·768px 너비의 가로 넘침, 캠페인 이동, 공유 완료 안내,
  제보 FAQ 펼치기 및 배포용 빌드의 페이지 표시 확인.
- 안전Dream 루트 링크가 공식 홈페이지 `/index.do`로 도달하는 것 확인.
- 전화 링크는 `tel:182`, `tel:112`로 구성했으며 실제 전화를 걸지는 않았다.
- API 프로브: JavaScript 구문과 인증키 미설정 시 실패 경로 확인. 인증된 실데이터 응답은 미검증.
- SNS 게시, 제보 접수, 실제 발견 여부 확인은 실행하지 않았다.
