# v1.8.1 — 브라우저를 안 가린다

v1.8.0의 「지나간 잉크」는 배포됐지만 **크로미움 계열에서만** 보였다. 사파리와
파이어폭스에는 그 CSS 문법이 아직 없어서, 아이폰으로 열면 아무 일도 일어나지
않았다.

규칙이 「어떤 사람에게는 있고 어떤 사람에게는 없는 것」이면 그건 규칙이 아니라
운이다.

## 없는 쪽에서만 같은 일을 손으로 한다

있는 쪽에서는 첫 줄에서 물러난다. 두 벌이 동시에 돌면 서로를 덮어쓴다.

구간 값(`cover 52%~78%`)은 CSS에서 그대로 옮겨 왔다. 한쪽만 고치면 브라우저에
따라 다른 화면이 나오므로, 그 사실을 값 옆에 적어 뒀다.

화면 안에 들어온 문단만 갖고 있다가 스크롤이 올 때만 칠한다. 대개 열 몇 개라
매 프레임 훑어도 싸다.

## 검사가 두 번 나를 잡았다

**첫째 — 처음 쓴 검사가 아무것도 보지 않았다.**

「타임라인 없는 브라우저인 척」을 `CSS.supports`를 가리는 것으로 만들었다.
그런데 그건 자바스크립트 쪽 답일 뿐이고, **CSS 엔진의 `@supports`는 그것을 보지
않는다.** 원래 규칙이 그대로 돌았고, 검사는 규칙이 아니라 규칙의 그림자를 보고
있었다. 대신 하는 길을 통째로 죽여 놓고 돌려도 통과했다.

판면 쪽 답과 CSS 규칙을 **둘 다** 없애고 나서야 대신 하는 길만 남는다.

**둘째 — 그렇게 고친 검사가 곧바로 진짜 버그를 잡았다.**

토큰(`#3d3d39`)에서 숫자만 뽑는 방식이 「3, 3, 39」를 만들고 있었다. 잉크가
옅어지는 대신 **새파랗게 어두워졌다.** 밝기로 17 → 6. 앞의 잘못된 검사는 이걸
통과라고 적었다.

|           | 판면 80% | 판면 15%                 |
| --------- | -------- | ------------------------ |
| 고치기 전 | 밝기 17  | 밝기 **6** (더 어두워짐) |
| 고친 뒤   | 밝기 17  | 밝기 **61**              |

이제 두 길이 같은 값을 낸다. 대신 하는 길을 죽여 세 판면 전부에서 잡히는 것도
확인했다.

앱에는 검사용 스위치를 넣지 않았다. 판면 쪽에서 「없다」고 답하게 하는 것으로
충분하고, 그래야 배포되는 코드에 검사만을 위한 자리가 생기지 않는다.
