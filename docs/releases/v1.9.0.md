# v1.9.0 — 지나간 잉크를 걷어낸다

v1.8.0에서 넣은 「스크롤하면 지나간 문단의 잉크가 가라앉는다」를 **전부 되돌린다.**

## 왜

세 번에 걸쳐 고쳤다. 없는 브라우저용 길을 따로 냈고(v1.8.1), 색을 한 단계 더
내렸다(v1.8.2). 검사는 세 판면 × 두 브라우저 경로에서 전부 통과했고, 밝기는
17에서 88까지 갔다.

그런데 실제로 읽는 사람 화면에서는 **바뀌는 건지 아닌지 알 수 없었다.**

검사가 통과한 값과 사람이 보는 것이 어긋나면, 어긋난 쪽은 사람이 아니다. 여기서
더 진하게 잡으면 읽기가 불편해지고, 원인을 더 파면 이 하나를 위해 브라우저마다
다른 길을 계속 관리하게 된다. 얻는 것이 그 값을 못 한다.

## 걷어낸 것

- 전역의 `.reading p` 규칙과 keyframes
- `Prose`와 `Passage`가 달던 `reading` 클래스
- 스크롤 타임라인이 없는 브라우저용 훅과 `App`의 연결
- 검사의 「굳은 잉크」 항목과 타임라인 없는 판면 한 벌

되돌리는 파일들에 이 작업 말고 다른 변경이 섞이지 않은 것을 먼저 확인했다.
`scripts/audit.mjs` · `App.tsx` · `global.css` · `Prose.tsx` · `Passage.tsx` —
다섯 파일 전부 v1.8.0 이후의 변경이 이 작업뿐이었다.

## 남기는 것

**v1.8.0 · v1.8.1 · v1.8.2의 릴리스 노트는 지우지 않는다.** 그때 실제로 나갔던
것이고, 지금 지우면 나갔던 사실만 없어지고 나갔던 일은 그대로 남는다. 그 세 편에
적힌 것 중 두 가지는 이 기능과 무관하게 남는 교훈이다 — 자바스크립트 쪽 답을
가려도 CSS 엔진의 `@supports`는 그것을 보지 않는다는 것, 그리고 토큰(`#3d3d39`)
에서 숫자만 뽑으면 「3, 3, 39」가 된다는 것.
