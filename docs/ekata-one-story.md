# EKATA One Story — 첫 구현

작성: jippy · 2026-09-06

## 범위

P0·P1·P2 기본형이다. 웹은 공개정보 표시와 공식 제보 연결을 맡고, 제작·검수·내보내기·게시 운영은 DEUS 앱의 역할이다. 첫 화면에 실종정보 Story를 배치하고, 캠페인 포스터는 ABOUT으로 이동했다.
현재 공급하는 다섯 건은 모두 가상 데이터이며 인물 사진은 사용하지 않는다.
실제 Safe182 API, 서버 프록시, PNG 내보내기, Instagram 게시·게시 이력은 웹의 기능 범위가 아니다.
운영 원칙은 실제 문서 경로인 `/ekata/policy/`에 배치했다.

## 데이터 경계

`CaseProvider → caseAdapter → MissingChildCase → EkataStoryCard / 큰 글씨 보기`

- 공급자 선택은 `lib/caseProvider.ts` 한 곳에서 한다.
- 현재 `sampleCaseProvider`가 기본 예시 또는 ID에 해당하는 예시를 비동기로 공급한다.
- `caseAdapter`는 프런트엔드 정규화 계약 검증이다. 실제 Safe182 응답을 흉내 낸 필드 매핑이 아니다.
- 인증된 응답을 확보한 후 서버에 Safe182 전용 adapter를 구현하고 이 계약으로 내려보낸다.
- 서버는 `verifiedAt`, `expiresAt`을 제공해야 한다. 확인 시각이 없거나 미래이거나 유효시간이 끝난 active 데이터는 stale로 바꾸고 식별 정보를 제거한다.
- stale/unavailable에서는 사건 카드를 숨긴다. 발견·귀가 상태를 추론하지 않는다.
- API 키는 서버 환경변수에만 둔다. 기존 인증 probe는 그대로 유지한다.

## 동일한 Story 원본

`components/EkataStoryCard.tsx`와 `style.css`의 `story-*` 영역이 유일한 Story 디자인이다.
기존 브랜드 포스터는 `CampaignPoster`와 `campaign-poster`로 분리했다.

- 부모 `.story-frame`이 inline-size container다. 출력 시 부모 너비를 1080px로 지정하면 카드가 1080×1920이 된다.
- 안전영역 토큰은 `--story-safe-top`, `--story-safe-bottom`, `--story-horizontal-padding`이다.
- `.story-device`, `.story-shell`, `.story-chrome`은 카드를 감싸는 장식이며 Story 원본이 아니다. export는 `.story-frame` 안쪽만 대상으로 한다.
- 기기 셸은 `.story-device`를 컨테이너로 삼아 `cqw`로 커진다. 카드의 `cqw`는 여전히 `.story-frame` 기준이라 조판이 바뀌지 않는다. 폭 상한(480px)은 `.story-device`로 옮겼다.
- chrome은 `--story-safe-top`, `--story-safe-bottom` 안쪽에만 그린다. 사건 정보를 덮지 않으며 `aria-hidden`이고 포인터를 받지 않는다.
- 검수 보류(`.story-hold`)도 `.story-frame` 안에서 9:16을 유지한다. 셸이 짧아져 chrome과 겹치지 않게 한다.
- 실제 인스타그램 UI를 그대로 흉내내지 않는다. 캡션으로 실제 게시물이 아님을 밝힌다.
- 길이에 따라 글자 크기만 조정하며 문장을 요약하거나 말줄임하지 않는다.
- 격자의 여섯 줄은 저마다 제 글의 높이를 갖고, 남는 세로 자리는 사진이 가져간다(`minmax(16cqw, 1fr)`). 글이 길어지면 사진이 먼저 물러선다.
- 글자 수 상한과 실제 DOM 넘침 검사를 함께 사용한다. 넘침은 줄마다와 격자 자체를 함께 재며, 초과하면 전체 웹 상세를 남기고 Story를 검수 대상으로 보류한다.
- 축소 조판은 150자·240자 두 단계다. 이름 크기는 다른 항목의 길이가 아니라 이름의 글자 수로 정한다.
- 사진은 `object-fit: contain`이며 필터·크롭·기울기를 적용하지 않는다. 로딩 실패는 실루엣으로 대체한다.
- 실제 게시용 export는 사진 로딩, 폰트 로딩, 최신 상태, 보류 여부를 확인하고 사람이 검수한 뒤 진행해야 한다.
- 샘플은 공식 데이터로 오인하지 않도록 카드 안에 개발용 표시와 가상 자료 출처를 넣는다.

## 웰뉴스 계정과의 톤앤매너

Story 카드는 언젠가 웰뉴스 계정에 그대로 올라간다. 그러므로 카드의 조판 문법은
에카타가 정하지 않고 **DEUS 앱의 카드 포지가 실제로 굽는 값을 따른다.**
근거는 `rwkor` 저장소의 `CardNewsPreview.kt` · `ReelCardNewsPreview.kt` ·
`CardCategoryLabel.kt` · `CardDateLabel.kt`다.

| 요소      | 값                                                             |
| --------- | -------------------------------------------------------------- |
| 바탕      | `#050505` 단색 + 아주 옅은 인쇄 그레인                         |
| 시그니처  | `#D05F5A` (분야 세로바 · 182 · 발행 칩 시작)                   |
| 발행 칩   | `#D05F5A → #551320` 대각 램프, 라운드 3/1080, 자간 0.03em      |
| 분야 라벨 | 세로바 4/1080 + 영문 대문자, 자간 0.12em, 좌상단               |
| 서명      | `wellknews_wordmark_original`, 폭 286/1080, 불투명도 0.9, 하단 |
| 조판 무게 | 사진 위, 활자 아래. 왼쪽 정렬                                  |

- 캠페인 초록(`--green`)은 카드 안에서 **점 하나**로만 등장한다 — 우상단 `EKATA` 마크의 정사각형(약 10/1080²). 면적은 발행 칩의 1/96이며, 카드에서 유일하게 «인쇄되지 않고 켜진» 것이다. 면으로 쓰지 않는다.
- 카드 밖 — 표지 한 줄, 셸 바깥선, 뒤편 후광 — 에만 초록이 남는다. 페이지는
  에카타, 유리 안쪽은 웰뉴스이며 그 경계를 지우지 않고 설계한다.
- 기기 셸과 스토리 chrome에는 브랜드색을 칠하지 않는다. 진행바는 인스타그램대로 흰색이다.
- 분야 라벨은 계정의 다섯 갈래와 같은 형태를 쓰고 단어만 `MISSING`으로 바꾼다.
  앱에 여섯 번째 갈래를 추가하는 것은 게시 시점의 과제다.
- 캠페인 정체는 우상단 마크(`EKATA` + 라임 사각형), 관계 표기는 워드마크 옆 콜로폰의 `An EKATA campaign` 한 줄이다. 경찰청 출처 표시와는 별개로 둔다.

## 웹 행동

- 샘플별 주소는 `/ekata/?sample=sample-a` 형식이다. GitHub Pages에서 직접 열 수 있고 뒤로가기에도 선택이 복원된다.
- 공유는 Web Share → URL 복사 → 수동 복사 순이다. 공유창을 취소한 경우 자동으로 클립보드를 덮어쓰지 않는다.
- 공식정보는 안전Dream HTTPS 도메인만 허용한다. 샘플에는 실제 사건 상세주소를 꾸며 넣지 않는다.
- 182·112는 전화 링크다. 사이트는 제보 내용을 수집하지 않는다.
- reveal, 읽기 위치 표시, 링크 반응은 유지한다. 포인터 빛과 tilt는 ABOUT 포스터에만 적용한다.

## 검증

- `node --test scripts/ekata-check.test.mjs`: 샘플 계약, 상태 만료·식별정보 제거, URL 검증, 공유·취소·복사 실패 분기.
- `npm run check`, `npm run build`.
- 브라우저에서 320·360·390·430·768·1024·1440px × 5개 샘플의 9:16 비율, 가로 넘침, 행별 넘침, 샘플 표시 확인.
- 같은 폭에서 기기 셸이 카드 비율을 바꾸지 않는지, chrome이 안전영역을 벗어나지 않는지, 검수 보류 화면이 셸을 채우는지 확인.
- 로컬 전용 검증 화면에서 이미지 실패와 수동 복사 UI, 키보드 포커스·주소 선택을 확인했다.
- reduced-motion 분기에서 포스터 포인터와 스크롤 업데이트가 설치되지 않는 것을 모의 설정으로 확인했다. CSS는 실제 운영체제 미디어 설정을 따른다.

## 후속 구현

P3에서는 서버 프록시·실제 응답 매핑·캐시·유효시간을 구현한다.
P5는 DEUS 앱에서 하루 한 사건 선정, 이미지 export, 검수, 게시 이력과 공개 종료 정리를 연결하는 범위다. 웹에 제작 화면이나 로컬 제작 이력을 추가하지 않는다.
현재 웹 구현만으로 Instagram 게시나 공개 종료 시 SNS 삭제가 자동으로 이루어지지는 않는다.

## 표기 규칙

- 메뉴는 한국어로 통일한다. 캠페인 · 만든 이유 · 운영 원칙이며 푸터도 같은 순서를 따른다.
- 영어 활자는 페이지 안 아이레이블(`WHY`, `THE NAME`)에만 남긴다. 탐색 경로에는 쓰지 않는다.
- 첫 화면 제목은 무엇을 찾는지 그대로 말한다. 표제 위에 공개정보 출처를 한 줄로 밝힌다.
- 제보 영역 끝에 자료 출처와 공식정보 확인 시각을 남긴다. 사건 정보를 반복하지 않는다.
- 카드의 실종일은 발행 칩 한 곳에만 적는다(`2026. 08. 14. 실종`). 사실 목록에서 반복하지 않는다.
- 카드 안의 자료 출처와 공식정보 확인 시각은 워드마크와 같은 줄 오른쪽 끝에 둔다.

## 공개 화면 정리

- 샘플 선택기를 공개 화면에서 제거했다. 다섯 샘플은 검증용 query 주소로 확인한다.
- 사건 정보는 카드에서 한 번만 표시하고, 확대가 필요할 때 큰 글씨 대화상자를 연다.
- 제보·공식정보·공유는 카드에 인접한 하나의 행동 영역으로 모았다. 별도 제보 섹션을 반복하지 않는다.
- ABOUT에는 캠페인 포스터, 공개 취지, 이름의 뜻만 남긴다. 제작·검수 UI는 추가하지 않는다.
- 정보 만료 시점에 화면을 갱신하며, 동적으로 도착하는 표시 요소에도 reveal을 적용한다.
